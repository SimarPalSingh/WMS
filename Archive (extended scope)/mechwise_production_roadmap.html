System architecture

Three-layer architecture: a React frontend served via CDN, a Node.js API backend with JWT auth and workshop-scoped queries, and a PostgreSQL database with Row-Level Security for multi-tenant isolation. All hosted in AWS Sydney (ap-southeast-2) for Australian data sovereignty compliance.

Key architectural decisions
Monolith first, microservices later. At launch with 1-10 workshops, a single Node.js API server handles everything. Don't split into microservices until you have 50+ workshops and clear scaling bottlenecks. Premature decomposition is the number one cause of startup overengineering.
Server-side rendering for the customer portal only. The workshop dashboard is a private SPA — no SEO needed, fast client-side navigation. The customer portal is public-ish (magic links) and benefits from SSR for initial load speed and link preview metadata.
Prisma ORM with raw SQL escape hatch. Prisma handles 90% of queries cleanly (CRUD, relations, pagination). The 10% that need raw SQL (BAS aggregate queries, complex joins for reports, bulk operations) use Prisma.$queryRaw. Don't fight the ORM — use it where it helps, escape where it doesn't.
No GraphQL. The API has well-defined screens with known data shapes. REST endpoints mapped 1:1 to screens (GET /api/dashboard, GET /api/clients/:id) are simpler to build, debug, and cache than a GraphQL schema for this domain.

Why not build as a mobile app?
Web-first, mobile-responsive. A responsive web app works on phones, tablets, and the wall-mounted screen — one codebase, no app store approval, instant updates. Mechanics use iPads or wall screens, not phones for primary work. The customer portal is a web page accessed via SMS link — no app install. A native iOS/Android app is a phase 3 consideration for mechanic-specific features (photo capture, barcode scanning via camera) — and even then, a Progressive Web App (PWA) may suffice.

Recommended immediate next steps
Step 1: Decide on build approach — Option A (hire a developer), Option B (small team), or Option C (build with Claude Code yourself). This determines budget and timeline.
Step 2: Register the domain (mechwise.com.au) and set up the project repository on GitHub.
Step 3: Set up the development environment — Vercel account, Railway instance, Supabase database, Stripe test account.
Step 4: Start Phase 1 Sprint 1 — auth system + database schema deployment + client/vehicle CRUD. Use the SQL schema file and UI prototypes from this project as the blueprint.
